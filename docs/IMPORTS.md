# Product CSV import · PLATFORM-003 contract

Administrator-only `configure` permission is the conservative initial policy. Requires an assigned warehouse; imported products belong to the company-wide catalogue. The warehouse identifies where the import was reviewed, not a stock location or owner. Company/warehouse/actor derive from authenticated context. Configurable staff approval limits remain unconfirmed.

`POST /api/v1/imports/products/preview`: clientOperationId, filename (1–200), csv (UTF-8, max 256 KiB), mapping (required sku/name/profile/unit, optional name_zh/handling; zero-based source column indices, distinct), reason (3–1000). Returns persisted batch id/code/version/status, source SHA256, parser/schema policy, mapping/headers, row proposals/issues, totals and ignored columns. Duplicate same source+mapping returns same scoped batch; different mapping is explicit new review. Max 500 nonblank rows/40 columns; no automatic delimiter/encoding/units guesses.

`GET /api/v1/imports/products?before=cursor`: latest 20 scoped batches, descending created_at/id, opaque stable cursor. `GET /api/v1/imports/products/:id`: current validation and original source/mapping for authorized recovery. `POST /api/v1/imports/products/:id/commit`: clientOperationId, expectedVersion. Checks current catalogue again, atomic insert, product identities + immutable import event, batch status committed/version increment. A structured 409 carries refreshed validation if data changed; no products/stock are written by failure. Identical operation replay returns original result. Committing an already committed batch with a new operation returns its recorded product IDs. Imported SKUs are create-only; existing SKUs block, even if values match. CSV spelling and leading zeros retained; edge whitespace in SKU/name is rejected for explicit correction. Case-sensitive exact SKU uniqueness follows existing catalogue, no guessed alias matching.

`GET /api/v1/imports/products/:id/errors.csv`: current validation report, same authorization; spreadsheet formula-leading cells neutralized and all fields CSV-quoted. CSV upload is treated as text data, never executed. No file URLs or public originals; original CSV is private database text included in backups. No external OCR or import worker needed for this bounded synchronous flow.

Profile and unit values must exactly match the existing supported catalogue choices. Optional blank Chinese/handling fields stay null. Profile does not enable/verify storage or traceability rules. Unknown columns are ignored only after explicit mapping and shown before commit. Prices, stock quantities, owner, batch/serial and pack conversions are outside this product import. Opening stock needs a distinct cut-over and reconciliation workflow.

No bulk reversal endpoint: product deletion would damage downstream references. Future correction must use reviewed product policy changes or compensating stock commands; import never writes stock. Source and mapping are retained. UI saves source/mapping drafts under user/company/warehouse; explicit local restore or batch reopen after reload, no automatic sync.
