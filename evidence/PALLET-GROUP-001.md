# Logical pallet grouping candidate

Base: 1a477c4. Authorized dispatcher/supervisor can create a named planning group linked to a planned trip and add/remove separate warehouse pallets. Group shows trip/current driver, pallet code, actual location, box count and current checked revision. It does not nest or physically move pallets, assign shipments, check manifests, verify a load or dispatch stock. No route, capacity or compatibility is inferred. A single physical pallet can belong to at most one active group, enforced by database uniqueness and guarded transaction; version conflicts, retry IDs, actor/company/warehouse checks and immutable membership history are recorded.

PASSED: npm run verify; 88 tests, 87 passed, zero failed, one native-only skipped; TypeScript and frontend build. Raw evidence: pallet-group-verification.txt. Added tests exercise multi-pallet creation/removal, no movement, scope, version conflicts, replay, duplicate membership, unauthorized access, history, v5 restore and v4 legacy restore. PGlite-only race serialization is not proof of PostgreSQL concurrency.

PASSED browser: full Express/PGlite started and applied migration 013 to an existing synthetic database without resetting it; Trips & drivers displayed the planning group controls, empty state and honest no-dispatch explanation. End-to-end group creation was BLOCKED because no ready shipment existed to create a planned trip in the browser test workspace. No extra tabs were opened after inspection. Physical device/tablet tests NOT RUN. Native PostgreSQL concurrency/migration/restore BLOCKED: two disposable PostgreSQL URLs unavailable.

Limitations: group membership is planning only; it does not itself assert every pallet belongs to the trip's shipment manifest or track destination-specific stop assignment. Existing per-shipment loading/dispatch checks remain authoritative. List currently capped at 100 groups; scalable pagination is still required. Customer-facing printable order form, automatic offline sync and OCR are not implemented. Current preview and source release must not be described as production-ready.
